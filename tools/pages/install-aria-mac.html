First launch

Installing Aria on macOS, and the Gatekeeper step

Aria is signed with a stable Apple identity but it is not notarised by Apple yet. On a first install, macOS will stop you once. Here is exactly what it says, why, and what to do — including how to check the file you downloaded is the real one.

The short version. Open the DMG, drag Aria into Applications, try to open it once and let macOS refuse. Then go to System Settings → Privacy & Security, scroll to the Security section, and click Open Anyway next to Aria. You will only do this once.

Step by step

  1. Download the right build. Apple Silicon for any M-series Mac, Intel for Macs sold before that transition. They are not interchangeable.
  2. Open the DMG and drag the Aria icon onto the Applications folder.
  3. Eject the DMG and open Aria from Applications — not from inside the mounted disk image.
  4. Let macOS refuse. This first refusal is what registers the app with the system so the next step appears.
  5. System Settings → Privacy & Security. Scroll down; a line about Aria being blocked will be there, with an Open Anyway button. Click it, confirm, and authenticate.
  6. Grant Microphone and Accessibility when asked. Accessibility is what lets Aria type into other apps; without it, dictation has nowhere to put the text.

What the messages mean

“macOS cannot verify that this app is free of malware”

This is the expected one. It means the app has a valid developer signature but has not been through Apple's notarisation service, which is a paid scanning step. It is not a virus warning and it is not a claim that anything is wrong with the file. Use the System Settings route above.

“Aria is damaged and can't be opened. You should move it to the Trash”

Despite the wording, this usually is not malware either — it most often means the download was incomplete or corrupted, or the app bundle was modified after signing. Do not force it open. Delete it, download again, and check the SHA-256 as described below. If the checksum matches and the message persists, tell us in an issue rather than working around it.

“The application is from an unidentified developer”

Older wording for the same situation as the first message.

Check that the file is genuine

Every release publishes a SHA-256 fingerprint next to each DMG. Comparing it takes ten seconds and it is the only way to be sure the file you have is the file we published:

In Terminalshasum -a 256 ~/Downloads/Aria-*.dmg
Compare withthe .sha256 file published beside the DMG on the release page
If they differdelete the file and download it again from the official page. Do not open it.

Only ever bypass Gatekeeper for a file that came from this site or the official GitHub releases page. If you found Aria somewhere else, that copy is not ours.

Why Aria is not notarised yet

Notarisation requires a paid Apple Developer account. Aria is made by one person and priced at €5 once; that account is on the list, and when it is in place this whole page becomes unnecessary. Saying so plainly seems better than letting you discover the warning on your own.

In the meantime, three things are true and checkable: the app is signed with a stable identity, so macOS keeps your Microphone and Accessibility permissions across updates; every DMG publishes its SHA-256; and updates verify size, checksum and signing identity before installing, rolling back automatically if the new version fails to start.

Questions

Is it safe to click Open Anyway?

For a file whose SHA-256 matches the one published on the official release page, yes — you are telling macOS you trust this specific app. The habit to keep is the checking, not the clicking.

Do I have to do this for every update?

No. Once, on first install. Updates keep the same signing identity, so macOS stops asking and your permissions are preserved.

Which build do I need?

Apple menu → About This Mac. If the chip line says M1, M2, M3, M4 or later, take Apple Silicon. If it says an Intel processor, take the Intel build.

Aria opens but types nothing. Why?

Accessibility permission is missing. System Settings → Privacy & Security → Accessibility, and switch Aria on. Without it macOS forbids any app from typing into another.

The microphone stays silent.

Check System Settings → Privacy & Security → Microphone, then System Settings → Sound → Input to confirm the device you expect is selected and its level moves when you speak.
